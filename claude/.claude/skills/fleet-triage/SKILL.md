`claude agents`(agent view)는 다섯 줄을 전부 똑같은 `blocked`로 보여준다. 데몬 예비 슬롯인지, 돈 떨어져 죽은 건지, 진짜 답을 기다리는 건지 구분이 안 된다. 이 스킬은 사람이 못 하는 조인을 대신한다. **보고만 하고, 아무것도 실행하지 않는다.**

1. **수집.** `python3 ~/.claude/skills/fleet-triage/fleet.py` 실행. 네 소스를 조인한다 — `claude agents --json --all`(명부), `ps -p <pid>`(`bg-spare` 유령 판별), 트랜스크립트 꼬리(진짜 마지막 활동 + 멈춘 이유), cwd별 `git status`(유실 위험).
2. **도달성 확인.** `ListAgents`를 호출해 스크립트 결과와 대조한다. 여기 안 뜨는 세션은 `SendMessage`로 못 건드리므로 attach 아니면 kill밖에 없다.
3. **믿을 신호를 고른다.** `startedAt`은 프로세스 시작 시각이라 거짓말을 한다 — 데몬이 예비 슬롯을 재활용하면 27일 전 작업이 "오늘"로 뜬다. **미활동 일수는 트랜스크립트의 마지막 타임스탬프로만** 판단한다.
4. **보고.** 분류별로 묶되, 사람이 실제로 결정할 것만 위에 올린다:
   - **사망** — 원인을 그대로 인용한다(429 spend limit, 인증 만료 등). 원인이 곧 재개 가능 여부다.
   - **정체 / 대기** — 몇 일째인지, 물고 있는 브랜치에 dirty 파일이 있는지.
   - **완료** — 결과가 커밋 안 된 채 남아 있는지. 리뷰 큐로 넘길 후보.
   - **진행 / 유휴** — 개수만. 나열하지 않는다.
   - **유령** — 개수만. 데몬 예비 슬롯은 정상이지 문제가 아니다.
5. **제안하되 실행하지 않는다.** 항목마다 다음 수(attach / kill / 재개 / 방치)를 한 줄로 붙이고 멈춘다. kill과 `SendMessage`는 사용자가 명시적으로 시킬 때만.

핵심: 세션 개수는 지표가 아니다. **커밋 안 된 채 잊힌 워킹트리**가 유실의 실체다.
